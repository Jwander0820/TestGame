# Game Shell Override

> 本檔覆寫 `../MASTER.md` 中不符合遊戲本體的 App Store landing page 建議。遊戲畫面不使用評分、裝置模型、下載 CTA、卡片網格或捲動式行銷段落。

## Subject and single job

- 主體：會因玩家死亡而心軟的荒謬 2D 平台遊戲。
- 對象：使用桌面或手機瀏覽器、希望短時間獲得挑戰與笑點的玩家。
- 單一工作：讓玩家立即理解三鍵操作並進入可玩舞台。

## Visual thesis

整個舞台像一張原本印刷工整、後來被遊戲系統用紅筆偷偷修改的兒童遊戲說明書。世界保持清楚、可愛；只有「系統心軟」介入時，紅色批改線、手寫註記與貼條才闖入畫面。

這個批改層是唯一高戲劇性的視覺簽名，其餘 UI 保持克制，避免每個元素都搶笑點。

## Layout

```text
┌──────────────────────────────────────────────┐
│ 小標題／死亡數                         暫停 │
├──────────────────────────────────────────────┤
│                                              │
│              16:9 可玩舞台                   │
│      （批改紅筆只在系統介入時出現）          │
│                                              │
├──────────────────────────────────────────────┤
│ [ 左 ] [ 右 ]                       [ 跳 ]   │
└──────────────────────────────────────────────┘
```

- Canvas 是頁面的主角，不使用額外英雄區或說明卡片。
- 桌面觸控列可隱藏，但鍵盤操作提示需可找到。
- 手機橫向時控制列貼近拇指自然位置並避開安全區。
- 關卡鏡頭底部約 20–25% 視為觸控安全帶；左右下角不得放置出生點、必要落點或關鍵字幕。
- 手機橫向仍是主要體驗；直向時不阻擋遊玩，Canvas 固定 16:9 完整縮放，控制列移至舞台下方。
- 直向只改變 DOM 外框與控制列排版，不改 Phaser 世界尺寸、鏡頭比例、素材比例或物理參數。
- 直向舞台較小屬可接受取捨；不得為了填滿螢幕而裁切或拉伸素材。

## Tokens

| Role | Value | Meaning |
| --- | --- | --- |
| `--paper` | `#FFF9E8` | 說明書紙張／UI 底色 |
| `--sky` | `#DDF4FF` | 舞台天空 |
| `--ink` | `#1D2A33` | 主文字與深色輪廓 |
| `--play-yellow` | `#FFD447` | 可互動物與主要按鈕 |
| `--grass` | `#1FAF9D` | 安全地形 |
| `--danger` | `#E95D5D` | 危險但非系統批改 |
| `--mercy-ink` | `#B9382C` | 系統心軟的批改層 |
| `--focus` | `#1769E0` | 鍵盤焦點環 |

- 顏色不能是唯一的危險或安全提示；搭配輪廓、形狀及動態。
- 一般文字與紙色需維持至少 4.5:1 對比。

## Typography

- 顯示：Fredoka 600／700，僅用於遊戲標題及短促系統訊息。
- 內文：Nunito 500／700；繁體中文優先回退至 `Noto Sans TC` 與系統無襯線。
- 工具／數字：等寬系統字型，只用在開發狀態，不出現在正式敘事 UI。
- 技術尖峰不得因遠端字型失敗而阻止開始遊戲；最終版本再評估自架字型子集。

## Controls

- 每個觸控目標至少 56×56 px，彼此間距至少 12 px；高於資料庫最低 44×44／8 px，容許平台遊戲的連續按壓誤差。
- 按下時使用內縮、陰影縮短及形狀變化，不只改顏色。
- 所有 DOM 按鈕有可見 `:focus-visible`，不得移除原生焦點後不補替代。
- 使用 `touch-action: none`、`overscroll-behavior: none` 避免遊玩時捲動或下拉重新整理。

## Motion

- UI 過場以 150–250 ms 為主，進場 ease-out、退場 ease-in。
- 一個畫面最多安排一個主要 UI 動畫；遊戲物理本身不算裝飾動畫。
- `prefers-reduced-motion: reduce` 時停用批改線抖動、背景漂移及非必要縮放；遊戲必要移動保留但避免鏡頭震動。
- 不引入 GSAP；尖峰以 CSS 與 Phaser 內建 tween 即可，減少非必要依賴。

## Prototype limits

此方向用於技術尖峰的可讀介面與程式繪製佔位圖，不代表最終美術已核准。像素、手繪、向量或混合風格仍待使用者選擇。
