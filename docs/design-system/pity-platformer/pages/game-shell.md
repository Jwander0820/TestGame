# 遊戲外框規格

- 狀態：已核准基準
- 最後更新：2026-08-10
- 上層規格：`../../../specs/SPEC-0005-art-style-baseline.md`
- 共用視覺系統：`../MASTER.md`

本檔收窄遊戲頁面的組成與狀態，不覆寫 `SPEC-0005` 的視覺論述，也不在元件內建立另一套色盤。

## 主體與單一工作

- 主體：會因玩家死亡而逐步心軟的正統可愛像素奇幻平台遊戲。
- 對象：使用桌面或手機瀏覽器、希望短時間獲得挑戰與笑點的玩家。
- 單一工作：讓玩家立即辨認三鍵操作、主角與下一落點，進入可玩舞台。

## 視覺論述

零死亡時，Canvas 必須先像一款完整的森林奇幻冒險。遠方王城、遺跡、草地與勇者建立可信世界；DOM 外框只提供克制的王室試煉標題、死亡數與暫停操作，不預告大型事故簿、施工或放水笑點。

首次死亡後，王城才以小型事故簿或蠟封承認正在觀察。死亡與援助升級後，守衛、繩索、木板、臨時橋與王命封條逐步侵入，但始終使用同一套奇幻色盤、材質與角色，不切換成教材、紅筆、試卷、補考或現代 Debug 介面。

喜劇焦點一次只放在一個世界介入事件。HUD 與 DOM 外框提供理解，不搶走主角、危險、落點或援助演出。

## 呈現階段

| 狀態 | DOM 外框 | Canvas／世界 |
| --- | --- | --- |
| 零死亡 | 王室試煉標題、死亡徽章、暫停；事故簿隱藏 | 正統清晨森林與正常機關 |
| 首次死亡 | 小型事故簿或蠟封短暫入場 | 陷阱揭露裂痕、尖角或缺口 |
| 偷偷放水 | 事故簿只顯示必要摘要 | 平台靠近、繩索或木板出現 |
| 公開援助 | 援助狀態短暫高亮 | 史萊姆、守衛或修繕隊成為焦點 |
| 荒謬繞過 | 王命封條／強制合格狀態 | 機關停用、終點靠近或通路公開建立 |

既有存檔若已包含死亡或援助，進場直接呈現對應階段；不得先閃現零死亡外框再跳轉。

## 版面

```text
┌──────────────────────────────────────────────┐
│ 王室試煉／死亡徽章                     暫停 │
├──────────────────────────────────────────────┤
│                                              │
│              16:9 像素可玩舞台               │
│      事故簿只在首次死亡後短暫進入安全區       │
│                                              │
├──────────────────────────────────────────────┤
│ [ 左 ] [ 右 ]                       [ 跳 ]   │
└──────────────────────────────────────────────┘
```

- Canvas 是頁面主角，不加入行銷 hero、評分、下載 CTA、裝置 mockup 或捲動卡片。
- 桌面可隱藏觸控列，但鍵盤操作提示需可找到。
- 上方 HUD 只放死亡徽章、暫停與當前必要狀態；大型事故簿不得常駐零死亡畫面。
- 關卡鏡頭底部約 20–25% 是手機橫向觸控安全帶；左右下角不得放出生點、必要落點或關鍵字幕。
- 手機橫向時控制列貼近拇指自然位置，並避開系統安全區。
- 直向時 Canvas 維持完整 16:9，控制列移至舞台下方；不裁切、拉伸或改變 Phaser 世界與物理比例。

## 元件 token 對照

本頁只使用 `MASTER.md` 的 Semantic／Component token。

| 元件 | 背景 | 文字／圖示 | 邊框／焦點 |
| --- | --- | --- | --- |
| 王室試煉標題 | `--color-ui-surface` | `--color-ui-ink` | `--color-ui-border` |
| 死亡徽章 | `--death-badge-bg` | `--color-ui-ink` | `--color-game-outline` |
| 事故簿 | `--incident-ledger-bg` | `--incident-ledger-ink` | `--color-ui-border` |
| 暫停／選單 | `--color-ui-surface` | `--color-ui-ink` | `--touch-control-border` |
| 觸控鍵 | `--touch-control-bg` | `--color-ui-ink` | `--touch-control-border`／`--touch-control-focus` |
| 援助高亮 | `--color-assist-primary` | `--color-ui-ink` | `--color-assist-magic` |

- 元件不得直接寫入新 hex 色值。
- 危險色不作為援助、焦點或一般按鈕主色。
- 事故簿與蠟封是死亡後狀態，不是每張面板的通用裝飾。

## 字體與文字

- 繁體中文使用 `"Noto Sans TC", "Microsoft JhengHei", system-ui, sans-serif` 基準；遠端字型失敗不得阻止遊戲開始。
- DOM 文字保持清晰，不為了模擬像素而使用難讀的小型中文點陣字。
- 標題可使用較重字重；一般狀態與字幕優先短句、清楚層級與至少 4.5:1 對比。
- 開發工具、等寬數字與內部 ID 不出現在正式敘事 UI。
- 圖像內不烘焙可變中文、死亡數或按鍵名稱。

## 控制

- 每個觸控目標至少 56×56px，彼此間距至少 12px。
- 左、右、跳圖示使用原創像素符號、清楚文字或一致且可追溯的 SVG；不使用 Emoji。
- 按下時使用 1–2px 內縮、陰影縮短與圖示位移，不只改色。
- 所有 DOM 按鈕具有可見 `:focus-visible`；不得移除原生焦點而不提供替代。
- 使用 `touch-action: none` 與 `overscroll-behavior: none`，避免遊玩時捲動或下拉重新整理。
- DOM 外框不得偽裝成可站立平台、危險物或援助目標。

## 動態與介入

- UI 進退場以 150–220ms 為主；進場 ease-out、退場 ease-in。
- 首次事故簿可使用一次短促滑入或蠟封落印；後續狀態更新不得重播長演出。
- 木板、繩索、守衛與史萊姆的主要動作由 Canvas 呈現，DOM 不另做重複動畫。
- 一個畫面最多一個主要 UI 動畫；遊戲必要物理動作不計入裝飾動畫。
- `prefers-reduced-motion: reduce` 時停用非必要抖動、漂移、縮放與蠟封彈跳，保留玩法必要動作並避免鏡頭震動。
- 不引入 GSAP、backdrop blur、濾鏡或 shader。

## 跨裝置與安全區

| Viewport | 外框規則 |
| --- | --- |
| 960×540 | 顯示完整標題、死亡徽章與暫停；驗證像素原始尺度 |
| 844×390 | 保留死亡徽章與暫停；事故簿不得壓住右上操作 |
| 667×375 | 可縮短標題，但不能隱藏必要狀態與三鍵 |
| 375×667 | Canvas 完整縮放，控制列置於舞台下方 |

每個 viewport 都要分別檢查零死亡、首次死亡與最高援助。事故簿、字幕、觸控鍵及暫停不得遮住主角、下一落點、揭露後危險或援助目標。

## 可存取性

- 一般文字與底色對比至少 4.5:1。
- 安全、危險、援助與焦點不得只靠顏色區分；搭配輪廓、裂痕、尖角、材質、圖示或動作。
- 螢幕閱讀器標籤使用操作目的，不把裝飾性的王城文案當成唯一名稱。
- 縮短標題或隱藏裝飾時，不得移除必要狀態。

## 實作與資產邊界

- 遊戲世界採純像素基準；DOM 外框採清楚、硬邊、共享 token 的介面，不要求兩者使用相同字型渲染。
- 目前 C01 主角與 C03 清晨森林只作造型／氣氛 reference，既有 PNG 不因本頁引用而取得正式核准。
- 正式資產由人工像素美術、生成後人工清稿或外包製作，仍依 `SPEC-0005` 保持未決。
- 素材缺失時使用同色盤、同輪廓規則的 fallback；不得改變碰撞、輸入、死亡、援助或保存狀態。

## 驗收檢查

- [ ] 零死亡畫面先讀成正統像素奇幻，沒有教材、紅筆、補考或大型事故簿。
- [ ] 首次死亡後才出現事故簿／蠟封，後續修繕依援助層級增加。
- [ ] 所有元件只引用 `MASTER.md` token，沒有頁面私有色盤。
- [ ] 觸控鍵達 56×56px、焦點可見、必要文字達 4.5:1。
- [ ] 四種 viewport 的三個視覺階段皆未遮擋主角、落點、危險或援助。
- [ ] 減少動態設定能停用非必要動畫。
