# SPEC-0004：進度碼、作弊碼與跳關反應

- 狀態：草案
- 負責人：Codex／使用者
- 建立日期：2026-07-16
- 最後更新：2026-07-16
- 關聯文件：SPEC-0001、SPEC-0002、SPEC-0003

## 問題與價值

靜態網站沒有帳號與雲端存檔。玩家更換裝置、清除瀏覽器資料或想保留目前關卡斷點時，需要一種不依賴伺服器的回復方式。同一個輸入入口也很適合承接傳統遊戲作弊碼、數字迷因與「直接跳到後面」的情境吐槽。

此功能需清楚區分：正式產生的「進度碼」負責可靠回復；人工設計的「作弊碼／彩蛋碼」負責笑點與可預期的特殊效果。

## 目標

- 玩家可把目前進度轉成一串可複製的離線進度碼。
- 另一個瀏覽器可輸入進度碼，預覽後回復到已註冊的安全 checkpoint。
- 同一入口接受少量人工設計的彩蛋碼，例如 `114514`、`AABB右右左`。
- 玩家輸入遠高於本機進度的有效關卡碼時，系統可以傷心吐槽但不得阻止或懲罰。
- 全流程維持純靜態、無帳號、無自有後端。

## 非目標

- 防止玩家分析、分享或修改自己的單機進度。
- 以進度碼保存任意世界座標、物理速度或演出中的臨時狀態。
- 將進度碼當成加密、授權、付費內容或防作弊機制。
- 在遊玩途中監聽一般文字鍵與方向鍵，造成角色操作誤觸。
- 支援玩家自行編寫任意程式或關卡指令。

## 入口與流程

- 標題畫面與暫停選單提供「進度碼」入口；關卡遊玩中不直接攔截作弊序列。
- 匯出時顯示目前關卡、checkpoint、已完成關卡及會一併保存的資料摘要，再產生可複製字串。
- 匯入時先解碼及驗證，只顯示預覽，不立即覆蓋本機進度。
- 玩家確認後才套用；若本機已有較後進度，需明示會覆蓋哪些資料並再次確認。
- 套用後只生成已註冊的關卡與 checkpoint 狀態，再由正常場景載入流程建立角色及世界援助。

## 正式進度碼提案

### 格式

- 前綴包含產品與格式版本，例如 `PP2-`。
- 本體使用適合人工複製的 Base32 或等價字元集，避開易混淆的 `0/O`、`1/I`。
- 末尾包含錯字偵測 checksum；它只防輸入錯誤，不宣稱防竄改。
- 解碼器對大小寫、前後空白與常見分隔符具容錯，但不得猜測無法驗證的內容。

### 必要內容

- 格式版本與遊戲內容版本。
- 當前關卡 ID 與已註冊的 progress marker ID。
- 已完成關卡及必要解鎖。
- 已觸發且仍需持續生效的世界援助。
- 會影響敘事的總死亡里程碑與已發現彩蛋。

### 不保存內容

- 任意座標、速度、當前跳躍幀或演出時間。
- 個人資料、裝置資訊、時間戳或可追蹤識別碼。
- 除錯資料與最近死亡事件 ID 清單。

## 人工彩蛋碼

| 輸入範例 | 建議效果 | 備註 |
| --- | --- | --- |
| `114514` | 一次性吐槽「嗯，這串數字聞起來怪怪的。」並記錄彩蛋 | 不改主線難度或 checkpoint |
| `AABB右右左`／`AABB-RRL` | 傳統作弊碼吐槽；具體效果待確認 | 只在進度碼輸入框提交後判定 |
| 代表 Boss／後期關卡的有效碼 | 允許套用並觸發跳關反應 | 依解碼後進度與本機進度比較，不只比對明文 |

彩蛋碼採內容資料化註冊，包含正規化後的輸入、一次性 reaction ID、效果 ID 與是否改寫進度。未註冊字串只能回報無法辨識，不能當成程式指令執行。

## 跳關反應

- 若匯入進度比本機最高進度明顯更後，標記 `large-progress-skip`，但仍顯示預覽與確認。
- 若目標是 Boss 關，建議首次反應：

> 真的假的啦，玩都不玩直接打魔王喔。很傷心欸 ( ´•̥̥̥ω•̥̥̥` )

- 反應是一次性的非阻塞吐槽；不能增加 Boss 難度、刪除道具、清除援助或拒絕載入。
- 從其他裝置合法搬移後期進度也可能符合條件，因此文案要保持玩笑感，不指控玩家作弊。

## 功能需求

### FR-1：確定性編解碼

相同的可保存進度需產生相同碼；相同有效碼需還原相同的標準化進度。

### FR-2：安全 checkpoint

解碼結果只能引用內容註冊表中存在的關卡、progress marker、援助與解鎖。未知 ID、組合不相容或版本過新時不得部分套用。

### FR-3：覆蓋前預覽

任何正式進度碼在修改本機狀態前，都需顯示來源版本、目標關卡、checkpoint 與主要差異，並由玩家確認。

### FR-4：原子套用

驗證全部成功後才一次替換保存狀態。套用中失敗時保留原本進度，不能留下半套用資料。

### FR-5：彩蛋隔離

純吐槽彩蛋碼不得偽造完成關卡、推進 blocker 連敗或降低主線難度；會改進度的作弊碼必須在內容設定明確宣告。

### FR-6：輸入隔離

作弊碼只在專用輸入介面提交後判定。介面關閉時，字母與方向鍵仍只依既有遊戲輸入規則運作。

### FR-7：可分享但不追蹤

進度碼不得含個資或裝置識別，也不需向伺服器登記。介面需提醒玩家：任何拿到此碼的人都能取得相同單機進度。

## 驗收條件

### AC-1：跨瀏覽器回復

- Given：瀏覽器 A 在已註冊 checkpoint 產生進度碼。
- When：全新瀏覽器 B 輸入、預覽並確認。
- Then：B 從相同 checkpoint 啟動，必要解鎖與持續援助一致。

### AC-2：損毀碼不改資料

- Given：輸入碼有錯字、checksum 不符或內容版本過新。
- When：玩家提交。
- Then：顯示可理解錯誤，本機原進度逐欄位保持不變。

### AC-3：未知內容不可注入

- Given：碼中引用未註冊的 level、marker 或 effect ID。
- When：解碼器驗證。
- Then：整筆拒絕，不建立任意座標、任意場景或未知效果。

### AC-4：Boss 跳關仍可玩

- Given：本機尚未完成前置關卡，玩家輸入有效 Boss 進度碼。
- When：玩家確認套用。
- Then：播放一次傷心吐槽並載入可玩的 Boss 安全起點，不提高難度或懲罰玩家。

### AC-5：彩蛋碼不污染門檻

- Given：玩家提交 `114514` 或另一個純吐槽碼。
- When：反應播放並保存彩蛋發現。
- Then：總死亡、blocker 連敗、checkpoint 與 active assist 全部不變。

### AC-6：遊玩輸入不誤觸

- Given：進度碼介面未開啟。
- When：玩家於關卡中依序按下相同字母或方向鍵。
- Then：只執行正常移動／跳躍，不觸發作弊碼。

## 測試策略

- 以固定 fixture 做編碼、解碼、checksum、正規化及 round-trip 測試。
- 對每個註冊 level／marker／effect 建立允許清單驗證。
- 測試版本過舊遷移、版本過新拒絕、單字元錯誤、截斷與亂碼。
- 測試預覽取消、覆蓋確認、寫入失敗與原子回復。
- 測試人工彩蛋碼大小寫、空白、分隔符及一次性反應。
- 瀏覽器驗證鍵盤焦點：輸入框開啟時不控制角色，關閉後立即恢復三鍵操作。

## 未決問題

- `AABB右右左` 的正式效果：只吐槽、暫時顯示隱藏路、解鎖關卡選擇，或開啟所有已取得援助？
- 進度碼是否完整保存死亡總數，或只保存已跨過的全域死亡里程碑以縮短字串？目前建議保存總數。
- Boss 跳關碼是否由遊戲內可正常產生，或只作為人工作弊碼？
- 是否需要 QR Code 顯示以方便手機轉移？第一版建議先不加入，維持零額外套件與短字串。
