# SPEC-0005：整體美術風格基準與首關收斂

- 狀態：已核准
- 負責人：Codex／使用者
- 建立日期：2026-08-10
- 最後更新：2026-08-10
- 關聯 ADR／規格：SPEC-0001、SPEC-0002、`docs/art-outsourcing/01-visual-direction.md`

## 問題與價值

目前首關同時混用三套語言：正統像素奇幻素材、平滑的程式向量背景，以及作業紙／紅筆式 DOM 與場景 UI。即使個別元素可用，組合後仍像測試畫面，並違反「開場先讓玩家相信這是一款完整奇幻冒險，世界在死亡後才逐漸失去專業形象」的既定承諾。

使用者於 2026-08-10 要求繼續推進遊戲設計並優化整體美術風格。本規格只收斂已選定的「假正經的奇幻冒險」方向，不把尚未核准的生成圖視為正式美術。

## 目標

- 建立一套可直接映射到 CSS、Phaser 程式繪圖與後續像素資產的三層視覺 token。
- 零死亡首屏只呈現可信、可愛、正統的森林奇幻冒險；作業紙、紅筆與現代 Debug 語言退出主視覺。
- 把「王城驗收造假」保留為世界觀內笑點，改用王室公會、蠟封、守衛、修繕隊、繩索與臨時木橋，並在死亡／援助後逐步侵入。
- 統一最近鄰、整數座標與清楚輪廓的像素呈現方式，讓正式素材與程式 fallback 不再像兩款遊戲。
- 撤回技術上不合格的 P1 主角與史萊姆試套，保留可追溯原始交付；森林地表僅維持有明確限制的 placeholder 狀態。
- 不改變首關物理、陷阱時序、死亡門檻、援助規則、保存資料或零援助可完成性。

## 非目標

- 本輪不製作或核准最終角色動畫、完整 tileset、背景插畫、音效或音樂。
- 不決定完整世界是 3+1、4+1 或 5+1。
- 不把 P0 風格圖直接裁切成正式遊戲背景，也不補寫其來源或商業授權。
- 不重做首關幾何、輸入、物理、存檔或同情導演門檻。
- 不追求逐像素完成整關；本輪是可持續擴充的 look-development 基線。

## 玩家流程

1. 玩家在零死亡狀態進入王城外圍的新手森林，看見勇者、可落腳地形、遠方王城與克制的王室試煉 UI。
2. 玩家首次遭到陷阱並死亡，畫面才出現小型王城事故簿或蠟封，承認世界開始觀察。
3. 死亡與援助層級上升時，臨時修繕、守衛介入、繩索、木橋與金／青色援助效果逐步增加。
4. 最高援助時，世界明顯放棄公正，但仍維持奇幻世界內的角色與材料，不切換成作業紙、紅筆或 Debug 介面。
5. 玩家在桌面與手機都能持續辨認主角、下一落點、揭露後危險與援助目標。

## 功能需求

### FR-1：單一視覺論述

- 遊戲世界採「正統可愛像素奇幻」作基底；喜劇來自原本體面的王城逐步公開放水。
- C01 的大圓盔、紅短披風、小圓盾與 C03 的冷青晨霧、遠方王城、低對比景深只作造型／氣氛 reference，不代表現有 PNG 已核准。
- 兒童教材、作業紙橫線、紅筆批改、試卷、補考與現代除錯視窗不得再作為主視覺。

### FR-2：三層視覺 token

- Primitive 層定義實際色值、像素步距、輪廓寬度與陰影階數。
- Semantic 層至少區分背景、遊戲層、安全地形、偽裝危險、揭露危險、援助、王室 UI 與可存取性焦點。
- Component 層定義主角、平台、臨時橋、事故簿、死亡徽章、選單與觸控鍵，不在元件內各自發明色盤。
- 本輪程式基準使用不超過 32 個主要不透明色；透明度只允許遠景霧氣、過場與非碰撞特效。

### FR-3：像素呈現契約

- Phaser 啟用 pixel-art、停用抗鋸齒並採整數像素相機／物件定位；DOM canvas 使用 `image-rendering: pixelated`。
- 程式 fallback 使用硬邊矩形／階梯輪廓與同一色盤，避免圓角卡片直接混入遊戲世界。
- 32×48 主角正式動畫的有效輪廓高度目標為 38–44px，腳底基線漂移不超過 1px；本輪程式 fallback 需落在同一可讀尺度。
- 24px 地形模組不得以任意小數倍放大作為正式視覺；碰撞矩形可與可見圖塊分離。

### FR-4：死亡前後視覺階段

| 狀態 | 主視覺 | 允許的世界介入 |
| --- | --- | --- |
| 零死亡 | 清晨森林、遺跡、王城、王室試煉徽記 | 不顯示大型事故簿、批改痕跡或施工笑點 |
| 首次死亡／觀察 | 同一奇幻世界 | 小型蠟封或事故簿首次出現 |
| 偷偷放水 | 奇幻基底不變 | 平台靠近、繩索、木板、守衛心虛動作 |
| 公開援助 | 援助成為短暫焦點 | 史萊姆、修繕隊、金色或魔法青色效果 |
| 荒謬繞過 | 世界公開放棄公正 | 王命封條、整段機關停用、終點主動靠近 |

### FR-5：資產狀態

- `chr_hero_idle_sheet.png` 每格含錯誤的雙重迷你角色，不再載入正式遊戲或進入正式 bundle；原始檔保留於生成輸出目錄作退件證據。
- `chr_hero_run_sheet.png` 維持退件，不進正式 bundle。
- `assist_slime_spring_sheet.png` 的有效高度不足且幀間近乎消失，不再載入正式遊戲；原始檔保留為 placeholder 證據。
- `tile_forest_ground.png` 只可透過人工確認的 atlas frame 暫用，不得宣稱為規則 tileset；正式版本仍需 24px 模組化重交。
- 新生成或外包資產在使用者核准、來源與授權補件前，只能放在候選輸出目錄。

## 遊戲規則與資料

- 視覺階段只讀取既有死亡數、阻礙死亡與已啟用援助，不建立第二份進度狀態。
- 所有視覺切換都不得改變碰撞體、平台座標、跳躍速度、陷阱觸發區或援助門檻。
- 素材載入失敗時仍使用同色盤 fallback；不得白畫面、隱藏碰撞物或阻塞關卡。

## 介面與輸入

- 桌面鍵盤：操作不變；焦點環保持清楚，外框不得偽裝成遊戲內危險物。
- 手機觸控：按鈕維持至少 56×56px，使用王室盾牌／石刻按鍵語言；不遮擋主角、下一落點或字幕。
- 畫面與回饋：零死亡時不顯示大型事故簿；首次死亡後才以短動畫顯示精簡狀態。
- 可存取性：文字與底色維持至少 4.5:1；安全／危險／援助不只依賴顏色，也使用輪廓、裂痕、尖角、動作或材質。
- 減少動態：遵守 `prefers-reduced-motion`，停用非必要抖動、漂移與縮放，但保留玩法必要動作。

## 邊界與失敗情境

- 素材缺失：使用像素 fallback，物理與流程不變。
- 既有存檔已有死亡：進場直接呈現對應事故簿／援助階段，不先閃現零死亡 UI。
- 直向手機：完整縮放 16:9 舞台，控制列移到舞台下方；不裁切遊戲世界補滿畫面。
- 低效能裝置：景深以少量靜態層與 Phaser 內建 scroll factor 實作，不加入昂貴濾鏡或逐幀 shader。
- 色覺差異：揭露後危險必須同時有形狀或動態差異。

## 驗收條件

### AC-1：零死亡首屏可信

- Given：全新進度且死亡數為 0。
- When：玩家開始第一關並觀看一秒。
- Then：先辨識勇者、可落腳地形、遠方王城與正統奇幻世界，畫面沒有作業紙、紅筆、補考或大型驗收檔案主視覺。

### AC-2：介入逐步出現

- Given：玩家從零死亡進入首次死亡，再進入最高援助狀態。
- When：比較三個狀態的實際遊戲畫面。
- Then：王城事故簿、臨時修繕與公開援助依序增加，且三張畫面仍共享同一奇幻色盤與材質語言。

### AC-3：揭露後危險可讀

- Given：偽裝危險已首次觸發。
- When：玩家重生並再次抵達。
- Then：危險以暖色之外的裂痕、尖角、缺口或動態提示在一秒內可辨識。

### AC-4：像素渲染一致

- Given：正式素材與程式 fallback 同時出現在 960×540 舞台。
- When：以 100% 與 400% 最近鄰放大檢查。
- Then：輪廓無抗鋸齒毛邊，畫面移動時沒有因小數座標造成的像素閃爍，程式背景不呈現平滑向量卡片感。

### AC-5：不合格素材撤回

- Given：建立正式產物。
- When：檢查資產清單與 `dist`。
- Then：不載入或發布錯誤的主角待機／跑步與史萊姆 sheet；森林地表仍以受限 placeholder 狀態載入，缺檔時 fallback 可完成關卡。

### AC-6：跨裝置可讀

- Given：960×540、844×390、667×375 與 375×667 viewport。
- When：檢查零死亡、首次死亡與最高援助關鍵畫面。
- Then：主角、下一落點、揭露後危險與援助目標不被 HUD／觸控鍵遮擋，必要文字維持可讀。

### AC-7：玩法回歸不變

- Given：零援助與最高援助測試狀態。
- When：完成首關、自殺重生、保存重載與終點搬近流程。
- Then：完成狀態、死亡數、援助數與既有驗收結果不因美術收斂而改變。

## 測試策略

- 單元測試：正式資產 manifest 不含退件 sheet；rendering 設定固定為 pixel-art、無抗鋸齒、整數像素。
- 整合測試：素材缺失 fallback、首次死亡事故簿顯示、既有存檔直接還原視覺階段。
- 瀏覽器操作：零援助與最高援助整關、終點事故與保存重載。
- 桌面／手機視覺驗證：960×540、844×390、667×375、375×667；至少保存零死亡與最高援助畫面。

## 效能與資產預算

- 不新增執行期相依套件、後端服務、濾鏡或 shader。
- 本輪不新增正式外部圖像；撤回錯誤公開 sheet，保留原始交付於不進 bundle 的生成輸出目錄。
- 垂直切片首次下載仍以壓縮後 5MB 內為努力目標；正式地表重交時不得為單一裁切框載入整張 1024×1024 object sheet。
- 新增資產仍需記錄來源、模型／人工處理、授權、尺寸、色盤與重現參數。

## 未決問題

- 最終角色與地形要由人工像素美術、生成後人工清稿或外包製作，待本基準實機驗收後決定。
- 目前 forest object sheet 何時換成真正 24px tileset，取決於下一輪 P1 小樣是否通過。
- 真實觸控裝置的角色尺度與按鍵手感仍需使用者後續試玩確認。
