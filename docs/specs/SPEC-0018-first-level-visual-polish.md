# SPEC-0018：第一關場景與王城入口細節修整

- 狀態：已實作並通過技術驗證；美術成果待使用者驗收
- 負責人：Codex／使用者
- 建立日期：2026-09-27
- 最後更新：2026-09-27
- 關聯規格：SPEC-0005、SPEC-0017
- 授權依據：使用者於 2026-09-27 要求「優化細化第一關」，指出「最後進去王國飛在天空上」及「素材不貼合」。

## 問題與價值

城門透明貼圖的可見底緣比終點平台高，角色一碰到位於半空的通關區便停止，通關截圖像是漂浮在門旁。森林背景裡的遠方王城固定在螢幕右上角，抵達終點仍與地面入口分離。兩者破壞到達王國的空間關係，也使不同來源素材顯得拼貼。

## 目標

- 城門可見底緣貼齊終點平台，入口與平台有連續石材細節。
- 可玩關卡的森林遠景保留原色盤與像素節奏，移除固定在天空的王城；標題仍可保留遠方王城作旅程提示。
- 通關時角色先落到入口前的平台，再走入打開的門洞；完成畫面不把角色定格在空中。
- 檢查首關起點、中段與終點的素材比例、接縫、遮擋及觸控畫面，修正本輪可明確重現的視覺瑕疵。

## 非目標

- 不重設關卡地形、陷阱、死亡門檻、援助時點、存檔格式或移動／跳躍參數。
- 不把其他收藏中尚未清稿的合成圖直接鋪入遊戲，也不宣稱第一關所有美術已最終核准。

## 玩家流程

1. 從標題進入森林關卡，看到與標題同色盤的森林深景，遠方王城不再固定懸於可玩畫面。
2. 玩家穿過既有機關抵達有地面支撐的石砌入口。
3. 一旦進入既有通關判定區，若仍在空中，角色於入口前落地；門洞打開，角色沿地面走入並淡出，然後顯示通關回饋。
4. 沒有新圖片或圖片失敗時，原程式背景及旗幟後備仍可通關。

## 功能需求

### FR-1：空間連續性

背景王城只用於標題。可玩場景使用同一批森林圖的無城堡衍生版本；終點城門可見底緣落在 `y=430` 平台頂，門前石材路徑與周圍地表同色盤，不遮住地刺或角色腳部。

### FR-2：進門演出

沿用現有 `goalZone` 與完成交易。演出只改呈現：角色在已安全判定的終點區內落到地面，步行至門洞並消失；缺少城門貼圖時仍顯示原旗幟及完成回饋。暫停、重開與減少動態偏好不得留下持續中的門洞或未還原角色。

## 遊戲規則與資料

通關觸發與既有陷阱／援助規則保持。只調整圖像位置、場景分層及完成後的視覺演出；無新保存欄位。

## 介面與輸入

- 桌面鍵盤及手機觸控：操作位置與判定不變，完成後均停止輸入。
- 畫面：960×540 原生舞台與 1280×800、375×667、667×375 viewport 可辨認門洞、地面及完成回饋。
- 音訊：不新增。
- 可存取性：減少動態偏好時縮短非必要動畫，仍顯示進門及完成狀態。

## 邊界與失敗情境

- 角色在門區半空中或已落地時完成；援助移動終點後亦需對準門洞。
- 缺少新增背景、既有城門或頁面失焦；不得阻止通關。
- 手機縮放下，門洞與主角不被介面遮住，地面頂線仍可見。

## 驗收條件

### AC-1：城門落地

- Given：正常或已移動終點的狀態。
- When：抵達終點。
- Then：門體與平台連續，角色在地面進門，最終畫面沒有懸空角色。

### AC-2：場景一致

- Given：首關起點、中段、終點。
- When：查看實際 Phaser 畫面。
- Then：森林深景不重複顯示固定的天空王城，地形、入口的像素密度與色盤相容，坑洞仍可辨。

### AC-3：回歸

- Given：零死亡、終點印章死亡後與最高援助路線。
- When：自動路線到達終點。
- Then：完成次數與死因維持，型別、受影響測試、建置均通過，缺圖後備可完成。

## 測試策略

- `npm.cmd run check` 與 `git diff --check`。
- 桌面、手機直向及橫向實際截圖檢查起點、中段、終點與完成狀態。
- 執行零死、終點印章、最高援助及缺圖後備的瀏覽器路線。

## 效能與資產預算

- 新增一張由使用者森林原圖衍生的本地無城堡遠景；不增加執行依賴、shader 或遠端請求。
- 門洞與地面細節以現有像素色盤程式繪圖，不另載圖片。

## 未決問題
