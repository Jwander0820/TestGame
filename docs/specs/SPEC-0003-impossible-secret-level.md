# SPEC-0003：必敗密道彩蛋關

- 狀態：草案
- 負責人：Codex／使用者
- 建立日期：2026-07-15
- 最後更新：2026-07-15
- 關聯文件：產品願景、SPEC-0002

## 問題與價值

主線必須維持「惡意但公平」，不能要求所有玩家用死亡換取通路；但隱藏彩蛋可以更徹底地顛倒平台遊戲規則：玩家進入一個以正常能力絕對無法完成的小關，只能透過一次次死亡逼迫遊戲逐步改寫自己。

此關的樂趣不是發現高難度技巧，而是意識到「失敗就是唯一的進度條」。

## 目標

- 建立一個經由水管、密道或反常探索進入的可選小關。
- 初始配置在已知角色能力下確實無法完成，而非僅僅非常困難。
- 每次關鍵死亡都永久改寫一段關卡，形成清楚的喜劇升級。
- 玩家最後透過世界援助完成關卡，取得彩蛋回饋後回到主線。
- 不發現或不進入此關，不影響主線理解、進度與結局。

## 非目標

- 把主線關卡設計成必須死亡固定次數才能通過。
- 讓玩家誤以為存在像素級跳躍或未公開操作可以破解。
- 無限死亡、隨機援助、永久困住玩家或清除主線進度。
- 提供影響主線平衡的必要能力、貨幣或最佳結局條件。

## 入口設計原則

- 入口藏在可被好奇玩家發現的位置，例如可進入的水管、假牆、回頭路或不合理的空隙。
- 入口附近至少有一個微弱但可讀的異常提示，避免只能靠亂撞每一面牆。
- 第一次進入後，主線的關卡選擇或彩蛋記錄提供再次進入方式，避免必須重做冗長路線。

## 不可能性契約

關卡初始阻礙需由可測量規則證明無法通過，例如：

- 缺口寬度大於角色最大水平跳躍距離，且沒有隱藏輸入能力。
- 終點被實體牆完全隔離，牆在首階段沒有可用開關。
- 移動平台的時序在角色最大速度下沒有重疊窗口。

不得只靠開發者主觀判斷「應該很難」。自動測試或關卡驗證器需記錄角色能力上限與阻礙參數。

## 建議流程

### Phase 0：遊戲假裝正常

- 玩家進入一個短小、看似高難度的房間。
- 旁白不預告「必敗」，讓玩家先自然嘗試。
- 第一次死亡快速重生，只留下略顯心虛的訊息。

### Phase 1：世界開始找藉口

- 第 2 次關鍵死亡後，出現層級 1 吐槽。
- 第 3 次關鍵死亡後，平台稍微變寬或缺口縮短，但仍刻意差一點點。
- 演出應讓玩家開始懷疑關卡真的在改變。

### Phase 2：援助公開化

- 第 5 次關鍵死亡後，NPC、彈簧、施工隊或系統批改層公開介入。
- 通路仍需要簡單的左／右／跳操作，保留玩家完成最後一步的參與感。

### Phase 3：世界徹底投降

- 第 7 次關鍵死亡後，提供確定可完成的荒謬繞過方式。
- 例：整個房間傾斜把玩家滑向終點、終點自己走過來、障礙排隊道歉後離場。
- 完成後頒發明確沒有用途但可收藏的獎勵，例如「合法通關證明（遊戲代打版）」。

實際死亡次數沿用已核准的 2／3／5／7 門檻；若試玩顯示節奏過長，需經規格變更而非暗中修改。

## 退出與安全

- 房間入口或暫停選單必須提供「先回主線」；退出不清除已發生的房間改寫。
- 玩家重新進入時保留援助階段，並用短訊息提醒房間已被改到什麼程度。
- 任何援助效果失敗時，最高階段需有不依賴該效果的保底出口。
- 彩蛋關內的死亡計入總死亡與彩蛋關計數，但不能推進主線特定阻礙的局部門檻。

## 功能需求

### FR-1：獨立進度域

彩蛋關使用自己的阻礙、死亡與援助狀態；不得污染主線局部連敗資料。

### FR-2：階段持久化

每次世界改寫完成後立即保存階段。重新整理、退出與再次進入均不得回滾已解鎖援助。

### FR-3：可驗證的初始必敗

關卡資料需提供可由測試驗證的不可能性理由與參數，並在最高援助後反向驗證存在可通過路線。

### FR-4：可退出

玩家在任何援助階段都能主動返回主線，且不受到文案羞辱或進度懲罰。

### FR-5：非必要獎勵

完成獎勵可收藏、可吐槽，但不影響主線操作能力、結局資格或必要蒐集百分比。

## 驗收條件

### AC-1：主線不依賴彩蛋關

- Given：玩家從未發現彩蛋入口。
- When：玩家沿主線完成遊戲。
- Then：不會缺少必要能力、敘事資訊或結局條件。

### AC-2：初始狀態無法獨力通過

- Given：彩蛋關處於 Phase 0，角色只有左、右與跳躍能力。
- When：以能力上限驗證所有合法路線。
- Then：沒有任何路線能抵達終點，並輸出明確的不可能性原因。

### AC-3：死亡推進世界

- Given：玩家尚未抵達最高援助階段。
- When：同一彩蛋阻礙的關鍵死亡跨過 2／3／5／7 門檻。
- Then：對應反應依序只觸發一次，改寫狀態立即保存。

### AC-4：最高階段保證完成

- Given：Phase 3 已生效。
- When：玩家依畫面提供的簡單路線操作。
- Then：不需隱藏技巧即可抵達終點。

### AC-5：退出後保留

- Given：玩家已觸發部分世界改寫。
- When：玩家返回主線、重新整理後再次進入。
- Then：彩蛋關維持已解鎖階段，不要求重複死亡。

### AC-6：死亡資料隔離

- Given：玩家在彩蛋關死亡。
- When：回到主線。
- Then：總死亡數增加，但主線阻礙的連續死亡門檻沒有改變。

## 測試策略

- 以角色速度、重力與跳躍速度計算或模擬初始最大可達區域。
- 對每個援助階段保存關卡快照，測試重載後狀態一致。
- 自動驗證 Phase 0 不可完成、Phase 3 存在可完成路線。
- 實際試玩觀察玩家何時察覺「死亡才是進度」，避免太早說破或太晚造成挫折。
- 測試每階段退出、重進、重新整理與保存資料損毀復原。

## 未決問題

- 第一個入口採水管、假牆或回頭路？
- 彩蛋關的主題是「施工中」、「系統測試室」還是主線場景的荒謬背面？
- 完成獎勵與收藏介面如何呈現？
- 玩家是否能在完成後選擇重看原始 Phase 0？目前建議只在獨立重播模式提供。
