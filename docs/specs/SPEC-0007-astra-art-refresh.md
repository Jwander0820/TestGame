# SPEC-0007：Astra 工作入口與像素奇幻重整

- 狀態：已實作、技術驗證完成；美術成品待使用者試看
- 負責人：Codex／使用者
- 建立日期：2026-09-20
- 最後更新：2026-09-20
- 關聯 ADR／規格：ADR-0001、SPEC-0001、SPEC-0002、SPEC-0005、SPEC-0006
- 授權依據：本次使用者要求重新整理專案以適合 Astra，並明確選擇「保留像素奇幻，重做角色、場景與介面的一致性」。

## 問題與價值

文件首頁仍描述已退件的素材，暫停快照被當成現在的工作入口；美術有規格卻缺少可比較的實際品質。玩家看到空白標題背景、方塊樹與不同像素密度的試套地表。

## 目標

- 以短治理文件、現況摘要及模組地圖支援 Astra 按任務取得上下文。
- 保留 SDD，但將使用者已授權的需求記錄成規格後持續實作，不重複詢問一般可逆選擇。
- 重做首關角色、森林／城堡景深、平台材質與 DOM 外框，建立可執行的共同視覺語言。
- 標題頁直接展示相同的森林與騎士，提供清楚的開始按鈕。

## 非目標

不更換 Phaser、升級依賴、變更模型設定或加入 OpenAI API；不改存檔、關卡幾何、物理、陷阱時序、援助門檻；不實作 SPEC-0003／0004；不提交或發布。舊素材及驗證產物保留。

## 玩家流程

1. 標題頁看見晨霧森林、王城和見習騎士，選擇踏上／繼續旅程。
2. 可玩場景延續同一組色盤、角色輪廓及材質。
3. 死亡後才出現事故簿，援助仍使用木橋、史萊姆與王室語彙。
4. 暫停、重玩、存檔及三鍵操作維持既有行為。

## 功能需求

- FR-1：根 README 提供安裝、啟動、驗證與模組入口；docs/STATUS.md 為當前事實入口，歷史日誌不自動成為現行需求。統一 check 命令，型別檢查涵蓋瀏覽器驗證工具並修復其既有型別缺口。
- FR-2：角色以可編輯的原創像素資料產生，維持 32×48 貼圖及原碰撞尺寸；只改顯示姿態，不改物理。
- FR-3：場景使用既有受限色盤、階梯輪廓、葉叢、樹幹、遠山與城堡；背景對比低於可站立平台及主角。
- FR-4：停用試套森林 atlas 的執行時載入，改用同色盤原創地表；原始檔保留供追溯。靜態平台視覺可重複鋪設而非水平拉伸像素。
- FR-5：標題插畫與遊戲共用繪圖／像素資料；外框減少厚框、大徽章與重複說明，保持清楚焦點及按鍵。
- FR-6：提供開發專用美術檢視頁，以記憶體進度切換零死亡、首次死亡、最高援助，避免為截圖清除玩家存檔；不進正式 bundle。

## 遊戲規則與資料

既有關卡、援助導演和 ProgressStore 為唯一狀態來源。動畫不能修改 body 尺寸、速度或重生位置。所有可碰撞頂面維持原 y 座標。

## 介面與輸入

- 桌面：方向鍵／A、D／空白鍵與原有選單操作不變。
- 手機：56px 以上觸控目標、12px 間距；直向完整 16:9 舞台，控制列在下方。
- 畫面：冷青遠景、苔綠中景、深青輪廓、紅披風、羊皮紙與王室金。顯示字體使用本機明體回退，操作使用黑體，不新增外部字型請求。
- 音訊：不新增。
- 可存取性：保留繁中標籤、焦點、reduced-motion；狀態不只靠色彩。

## 邊界與失敗情境

窄螢幕選單可捲動但開始按鈕必須可達；暫停時不接受玩法輸入；資產皆可由本地程式重建，不依賴遠端服務。舊存檔、重生和最高援助需保留。歷史 375×667 額外死亡案例獨立記錄，不修改預期掩蓋。

## 驗收條件

- AC-1：Given 新接手代理，When 閱讀 AGENT、STATUS 與 README，Then 能找到現在範圍、程式入口、命令和未驗項目，不需掃描歷史日誌。
- AC-2：Given 初始／暫停／重進，When 顯示標題或場景，Then 角色和森林沿用同一色盤；無試套 atlas 網路請求、無退件角色；零死亡沒有事故簿。
- AC-3：Given 四種規定 viewport，When 顯示標題與首屏，Then 無水平溢出、Canvas 維持 16:9，必要控制可達。
- AC-4：Given 既有存檔及測試路線，When 執行驗證，Then 型別、單元、正式建置通過；零援助 0 死及最高援助 21 死可完成。未執行或失敗的路線如實記錄。
- AC-5：Given 代表性實際截圖，When 交付，Then 區分技術通過與使用者美術驗收；不能因測試通過就宣稱美術已核准。

## 測試策略

保留既有單元／幾何回歸；對像素資料驗證尺寸、色盤及腳底基線。執行 typecheck、test、build、diff check。Browser 技能檢查桌面與 960×540、844×390、667×375、375×667；使用既有整關測試頁驗證視覺變更未破壞玩法。

## 效能與資產預算

不新增執行依賴及遠端字型；新美術以程式與少量像素矩陣保存，靜態景物只在建立時繪製。來源為本專案原創程式資產，禁止納入來源不明圖片。主要不透明色不超過既有 32 色；背景不使用模糊濾鏡。

## 未決問題

最終美術是否滿意由使用者檢視實際畫面決定；真人觸控手感不能以桌面 viewport 模擬取代。
