# 2026-07-16：場景生命週期狀態機重構

## 背景

`VerticalSliceScene` 原本以 `dying` 與 `completed` 兩個布林值分散判斷更新、死亡、重生及完關。現有程式雖有防重入，但兩個旗標理論上能形成「同時死亡且完成」等非法組合；新增轉場或彩蛋關時也容易遺漏其中一個判斷。

此區直接關聯 SPEC-0002 AC-2「一次生命只記一死」，以及死亡演出與完關流程不得同時成立的安全性。

## 實作

- 新增與 Phaser 解耦的 `SceneLifecycle`，只允許以下轉換：
  - `playing → dying → playing`
  - `playing → completed`
  - 場景重新建立時由任何狀態明確 `reset → playing`
- 第二次致命碰撞、死亡中的完關、完成後的死亡與無對應死亡的重生都會被拒絕。
- `VerticalSliceScene` 的 update、死亡、重生、完關及彈簧安全判斷全部改讀同一狀態機。
- 不變更死亡計數、900 ms 重生時間、玩家物理、援助門檻、存檔格式或使用者文案。

## 驗證策略

本輪以純狀態機單元測試直接覆蓋所有合法與非法轉換，再執行完整型別、測試及正式建置。依風險分層策略不重複人工瀏覽器操作；實際結果於完成後補記。
