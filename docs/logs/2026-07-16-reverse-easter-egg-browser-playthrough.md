# 2026-07-16：反向零價值金幣實際碰撞整關驗證

## 目標

補齊 SPEC-0001 Beat 1 與 AC-8 的實際瀏覽器證據：玩家必須真的能從起點向左，穿過單向平台底面、落在兩層膠帶、觸發零價值金幣，再折返完成主線。

## 被淘汰的牆鐘輸入方法

第一版測試以正式 `/dist/` iframe 送出固定延遲的左移與兩次跳躍：

- 第一次成功觸發彩蛋、折返主線、死亡 6 次完成，並在重載後確認一次性保存。
- 後續兩次沒有觸發彩蛋；死亡仍為 0，角色最後停回安全地面。
- 原因不是平台碰撞錯誤，而是外框以牆鐘猜測角色落地時刻；瀏覽器排程變動時，跳躍事件可能在 `grounded` 前被消耗。

此方法無法穩定證明物理路線，因此整套結果不列入驗收，測試外框改為幀驅動。

## 幀驅動方法

開發驅動器只使用正式 `PlaytestFrame` 提供的 `x`、`y`、`grounded`，所有輸入仍經過正式 `ActionState`：

1. 起點實際落地後才按左與第一次跳躍。
2. 角色中心進入第一層水平範圍後放開左方向。
3. 實際落在第一層且 y 小於 350 後，才送出第二次跳躍。
4. 進入秘密平台／觸發區高度後轉向右側。
5. 首次觸發時以隔離的真實 localStorage 保存，呼叫真正頁面 reload。
6. 全新 store 與場景第二次走過秘密平台；因彩蛋已保存，不應再發布完整吐槽。
7. 沿零援助主路線跳躍區抵達終點。

## 最終結果

- 完整流程連續執行兩次皆通過。
- Navigation Timing：`reload`。
- 首次狀態文字：「你特地往左找到了 8 枚沒有用途的金幣。很會。」
- 首次狀態：死亡 0、active assists 0、彩蛋 ID 1 筆。
- 重載後確實再次抵達秘密平台高度，完整吐槽發布 0 次。
- 終點狀態：死亡 0、active assists 0、彩蛋 ID 仍為 1 筆。
- console warning／error 均為 0。

## 驗收判斷

AC-8 的程式可達性與不阻塞主流程已有完整自動整合證據，可標記通過。真人試玩仍需評估入口是否容易被喜歡探索的玩家察覺，以及兩段跳躍與吐槽的喜劇節奏，但這不再是功能正確性缺口。
