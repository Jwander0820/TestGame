# 2026-07-16：零援助路線可達性審查

## 審查目的

補做 SPEC-0001 尚未完成的整關連續試玩與零援助路線驗證，確認玩家不依賴同情援助也存在可完成的主要路線。

## 實際操作限制

- 本機頁面可由標題正常開始，鍵盤與觸控事件也能送入頁面。
- 目前自動瀏覽器介面只能送出立即按下／放開，無法維持 Phaser 所需的「持續按住方向並同時跳躍」。
- 單次觸控點按可讓角色短距離移動，但用大量瞬間點按冒充真實通關會失真，因此本次沒有把它記為整關實玩通過。

## 發現問題

- `warning-strip` 前平台原本右緣約為 x=973，後平台左緣約為 x=1,216，水平間距約 243px。
- 目前移動速度 240px/s、跳躍速度 470px/s、重力 1,150px/s²；同高度完整跳躍的理論水平距離約 196px。
- 因此原始零援助路線不可能跨過警告帶，與既有設計判斷「主路線即使零援助仍能通過」矛盾。

## 修正內容

- 將警告帶前平台中心由 x=865 調整為 x=900。
- 將警告帶後平台中心由 x=1,360 調整為 x=1,320。
- 修正後平台空隙為 168px，同高度跳躍保留約 28px 理論餘裕；危險帶仍橫跨空隙，不會失去陷阱功能。
- 將世界、物理、出生點、平台與危險帶尺寸抽離到 `levelOneLayout.ts`，避免場景與測試各自維護數字。
- 新增整條主要平台路線的可達性測試；每個必要跳躍至少保留 20px 理論水平餘裕。

## 驗證結果

- `npm test`：5 個測試檔、20 項測試全數通過。
- `npm run build`：TypeScript 與 Vite 正式建置通過。
- 修正版桌面起點、第一個缺口與後續平台入口顯示正常。
- 瀏覽器 console：無 error／warning。

## 仍待驗證

- 真實鍵盤從標題連續操作至結算。
- 真實觸控裝置同時按住方向與跳躍完成整關。
- 零援助與 tier 4 援助路線的實際操作手感；幾何計算只證明理論可達，不等同試玩驗收。
