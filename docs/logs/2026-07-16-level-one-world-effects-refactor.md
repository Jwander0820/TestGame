# 2026-07-16：第一關世界與援助效果重構

## 背景

第一關的援助規格以任意字串保存 `effectId`，場景再用另一處 `switch` 解讀。兩端沒有編譯期關聯，新增效果時可能漏掉處理器或因拼字錯誤直到遊戲執行才失敗。此外，平台、危險帶、彈簧、繞道與援助視覺都由 `VerticalSliceScene` 直接建構，使流程控制與世界呈現持續耦合。

## 決策與實作

- 建立 `LEVEL_ONE_EFFECT_IDS` 與 `LevelOneEffectId`，讓第一關反應資料受 TypeScript 聯集型別約束。
- 保留存檔解析的向後相容性；從存檔讀出的字串在套用前仍需經 `isLevelOneEffectId` 執行期守衛。
- 新增 `LevelOneWorld`，集中平台、單向平台、危險帶、彈簧、橋梁、繞道與危險帶退役的 Phaser 物件生命週期。
- 將援助幾何移入 `LEVEL_ONE_ASSISTANCE_LAYOUT`，避免效果處理器內散落座標與數值。
- 抽出共用的 `addGameText`，保持場景與世界模組的字體設定一致。
- `VerticalSliceScene` 保留玩家流程、死亡演出、彩蛋、進度標記與完關協調，不再持有援助世界物件。

## 行為不變範圍

- 2／3／5／7 援助門檻與反應順序不變。
- 平台、危險帶、彈簧、橋梁及繞道的座標、尺寸與碰撞設定不變。
- 存檔格式、效果 ID、角色速度、跳躍力及使用者文案不變。
- 未新增正式相依套件，仍維持純靜態網站建置。
