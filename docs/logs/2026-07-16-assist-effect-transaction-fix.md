# 2026-07-16：修正援助效果的交易式保存

## 發現

SPEC-0002 AC-8 要求效果識別不存在或套用失敗時，遊戲需記錄錯誤、繼續重生，且不得保存半套用狀態。既有流程卻先由 `LevelOneSession` 保存導演結果，把 reaction 與 active effect 寫入進度，再由場景建立世界物件。

若世界物件建立失敗，畫面沒有援助，但存檔已宣告援助生效；重載後也會持續嘗試還原錯誤效果。此行為與已核准規格矛盾。

## 修正

- `SympathyDirector` 的結果新增 `stateWithoutReaction`，代表死亡已計數、但尚未消耗本次 reaction 的安全基線。
- `LevelOneSession.recordDeath` 成為效果交易邊界：
  - 沒有機械效果的吐槽反應直接提交。
  - 世界效果回報成功後，才提交 reaction 與 active effect。
  - 世界效果回報失敗或擲出例外時，只提交死亡基線並回傳一般死亡結果。
- 場景先進入死亡鎖與關閉角色物理，再透過工作階段套用效果；不論效果結果，既有 900 ms 重生流程都會繼續。
- 失敗的 reaction 不會被標記已觸發，因此下一次有效死亡仍能重試，避免永久遺失援助。

## 驗證結果

- 新增純導演測試，證明候選狀態與死亡基線只在 reaction／effect 欄位有預期差異。
- 新增工作階段測試，涵蓋效果回傳失敗、意外擲出例外、死亡照常保存，以及下一次死亡重試成功。
- `npm run typecheck`：通過。
- `npm test`：10 個測試檔、42 項測試全部通過。
- `npm run build`：正式靜態產物建置通過；gzip 約 367.68 kB。
- 沒有新增正式套件；Vite 仍只有既有的 Phaser bundle 大小提示。
- 本項修正狀態交易且已有針對性自動測試；依分層驗證策略不重跑人工瀏覽器操作。
