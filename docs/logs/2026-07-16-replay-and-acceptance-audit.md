# 2026-07-16：重玩流程修正與 SPEC-0001 驗收稽核

## 發現問題

- 完成關卡後選擇「回標題」，再從標題開始時只會恢復已完成場景；角色 body 已停用，無法再次操作。
- Phaser `scene.restart()` 會重用場景實例，但原本沒有重設 `completed`、`dying`、出生點、援助效果集合及物件參照。
- 因此重玩或清除紀錄後，可能從舊 checkpoint 出生、保持完成／死亡狀態，或略過已解鎖援助的物件重建。
- 原地彩蛋計時器只重設計時起點；清除紀錄後仍保留「曾觸發」旗標，無法重新發現。

## 修正內容

- 新增純資料 `restartLevel()`：回到 `start`、清除 checkpoint 與局部連死 streak、將 completed 改回 false，同時保留累積死亡、死因、已播放反應與 active assists。
- 「重來本關」、「再寫一次」及完成後從標題重新開始，皆使用相同狀態轉換。
- 完成紀錄的標題按鈕由「繼續」改成「再寫一次」。
- 場景每次 `create()` 前重設執行期旗標、出生點、危險帶／彈簧參照與已套用效果集合，再依保存狀態重建。
- `IdleTrigger` 新增完整重設，讓清除保存後可重新發現等待彩蛋。

## 驗證結果

- `npm test`：5 個測試檔、22 項測試全數通過。
- `npm run build`：TypeScript 與 Vite 正式建置通過。
- 瀏覽器實際走過「開始 → 暫停 → 重來本關」，回到可操作場景。
- 瀏覽器實際完成清除紀錄的四秒內二次確認，清除後回到可操作場景。
- 正式 `dist` 由一般靜態伺服器放在 `/dist/` 子路徑提供；HTML、CSS、JavaScript 皆回應 200，遊戲可開始。
- 開發版與正式子路徑版 console 均無 error／warning。

## 驗收判斷

SPEC-0001 仍維持「已核准」，不升級為「已驗收」。詳細缺口與證據見 `docs/testing/SPEC-0001-acceptance-matrix.md`；主要剩餘門檻是真人鍵盤、真實多點觸控整關完成，以及起點反向探索彩蛋。
