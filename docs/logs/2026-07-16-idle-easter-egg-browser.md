# 2026-07-16：正式產物原地等待彩蛋驗證

## 驗證目標

依 SPEC-0002 AC-9，以正式 `/dist/` 同時驗證真實焦點、背景時間排除、8 秒門檻、一次性保存及重載後不重播。

## 流程

1. 在隔離的瀏覽器來源清除正式進度 key，載入 `/dist/` 並開始遊戲。
2. 聚焦遊戲舞台等待 4 秒，確認尚未觸發。
3. 將焦點移到 iframe 外的測試按鈕，確認遊戲文件失去焦點，再等待 8.5 秒。
4. 背景等待結束時核對保存，`idle-apology` 仍不存在。
5. 重新聚焦遊戲舞台並等待首次觸發，記錄實際牆鐘時間、狀態文字、死亡與援助。
6. 重載正式 iframe，再等待 8.5 秒，確認保存仍只有一筆且完整文案不重播。

## 初次測試修正

首次執行的遊戲行為其實正確，但測試報告為失敗：

- 彩蛋已觸發，背景時間未誤算，所有保存欄位正確。
- 測試在呼叫 `focus()` 後先等待 150ms 確認焦點，才開始量觸發時間，因此只記到 7,938ms。
- 8 秒門檻實際已包含前面的 150ms；這是碼表起點錯誤，不是遊戲提前觸發。

將碼表起點移到提出聚焦要求的當下後，重新執行完整流程。

## 最終結果

- 連續兩次完整流程皆通過。
- 背景等待 8.5 秒：兩次皆未發現彩蛋。
- 回復焦點後觸發時間：8,108ms、8,034ms。
- 首次狀態文字：「你是在等遊戲先道歉嗎？」
- 首次保存：`idle-apology` 恰好 1 筆、死亡 0、active assists 0。
- 重載並再等待 8.5 秒：彩蛋 ID 仍恰好 1 筆，狀態維持「方向鍵或 A／D 移動，空白鍵跳躍。」
- iframe 捕捉到的 console warning／error 皆為 0。

## 驗收判斷

SPEC-0002 AC-9 已有正式產物端到端證據。8 秒門檻可在真人試玩時再校正喜劇節奏，但背景時間排除、一次性保存及不影響死亡／援助的功能正確性不再是缺口。
