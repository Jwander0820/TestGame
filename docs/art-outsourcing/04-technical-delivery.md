# 技術交付與授權規格

- 狀態：外包評估草案
- 建立日期：2026-07-17
- 最後更新：2026-07-17
- 目前遊戲技術：Vite + TypeScript + Phaser

## 現有遊戲基線

- 邏輯畫布：960×540，16:9。
- 關卡世界：目前深化後第一關約 3000×540，可水平捲動。
- 現有角色碰撞尺寸：約 28×39，程式佔位圖約 34×42。
- 目標主角美術：約 32×48，正式尺寸需先做碰撞與手機縮圖測試。
- 暫定地形模組：24×24；外包方若建議 16×16 或 32×32，需提供同畫面比較及修改成本。
- 現有遊戲尚未啟用 pixelArt 模式；正式接入像素資產時由開發端調整 nearest-neighbor、抗鋸齒與整數座標策略。

## 必要交付格式

### 圖像

- PNG，RGBA，透明背景。
- 無有損壓縮、無 JPEG 雜訊、無白色或半透明去背毛邊。
- 不在圖像內烘焙繁體中文、按鍵名稱或可能修改的對話。
- 背景層若不透明，可交付 PNG；重複背景需清楚標示可平鋪方向。
- 所有素材保持原始像素尺寸，不預先放大 2 倍、4 倍或套用平滑縮放。

### 動畫

- 優先交付等尺寸格狀 spritesheet PNG。
- 另附單幀 PNG 或原始工作檔，方便修正。
- 每列／每個動畫需附：動畫名稱、幀順序、建議 FPS、是否循環、碰撞／錨點備註。
- 角色各幀畫布尺寸一致；腳底基準與水平中心不可無故跳動。
- 若提供 JSON atlas，需同時保留未打包的來源圖，不只交付工具專用格式。

### 原始工作檔

- Aseprite `.aseprite` 為優先；亦可使用 PSD、Krita 或其他可保留圖層與動畫的格式。
- 不得只交付放大後預覽圖或無法編輯的影片。
- 圖層需有可理解名稱，例如 `body`、`helmet`、`cape`、`shield`、`shadow`。

## 命名規則

使用小寫英文、連字號或底線，避免空白與中文檔名。建議：

```text
chr_hero_idle_sheet.png
chr_hero_run_sheet.png
chr_hero_death_sheet.png
env_forest_bg_far.png
env_forest_bg_mid.png

assist_guard_bridge_sheet.png

```

## 錨點與留白

- 主角：腳底中央為主要定位基準，頭盔與披風動畫不得改變腳底基準。
- 地面物件：底部中央或左下角為基準，交付時註明。
- 飛行／特效：中心點為預設基準，若需跟隨角色則另附偏移建議。
- spritesheet 每格留白一致；不得因某幀披風伸出而裁掉像素。
- 互動物件的可見輪廓可超出碰撞箱，但不能讓玩家誤判安全頂面。

## 像素品質

- 使用清楚像素群，不混入任意大小的模糊筆刷。
- 相同材質採一致光源方向與陰影階數。
- 主角、危險物與安全平台在 480×270、360×203 縮圖下仍可區分。
- 角色與物件輪廓不得依賴單一顏色；必要時使用深色外輪廓或明暗切面。
- 背景對比與細節低於遊戲層，避免搶走落腳點。
- 前景裝飾不得遮蔽必要平台、陷阱與角色腳部。

## 效能與檔案預算

- 垂直切片所有正式圖像壓縮後以 5 MB 內為努力目標，並保留聲音與程式空間。
- 優先重用 Tileset、共享特效與鏡像動畫，不為每段平台製作獨立大圖。
- 單張紋理建議不超過 2048×2048；若超過需先與開發端確認低階行動裝置相容性。
- 大型背景拆成可循環層或合理尺寸區塊，避免整關 3000×540 全部烘焙成一張無法重用的圖。

## 生成式 AI 與智慧財產

外包方須在報價及交付時提供：

- 是否使用生成式 AI；若有，列出服務／模型名稱與主要用途。
- 哪些內容由模型生成、哪些內容經人工重繪或清稿。
- 使用條款是否允許本專案永久商業使用、修改、散布與再授權遊戲成品。
- 使用的付費素材、字型、筆刷、Tileset 或參考資產及其授權證明。
- 確認未直接描摹、拼貼或複製第三方角色、遊戲畫面、Logo 或未授權素材。

最終合約應明確包含：

- 委託方可永久於遊戲、網站、宣傳與衍生版本中使用及修改交付物。
- 是否為專屬授權或著作財產權移轉，由報價明列。
- 外包方可否公開作品集，以及可公開的時間點與範圍。
- 發現權利爭議、模型使用限制或素材來源不明時的修正／替換責任。
