# 同情導演實作設計

- 狀態：第一階段已實作
- 日期：2026-07-16
- 關聯：SPEC-0001、SPEC-0002、ADR-0001

## 目的

將已核准的 2／3／5／7 局部援助門檻落成與 Phaser 解耦、可重現、可保存的純資料核心，再由關卡場景把 effect ID 轉成世界內演出。

## 邊界

```text
死亡碰撞
   ↓ 建立 DeathEvent（只建立一次）
SympathyDirector（純資料）
   ├─ 更新全域／關卡／阻礙狀態
   ├─ 固定排序選出最多一個 Reaction
   └─ 回傳死亡基線與含 Reaction 的候選狀態
           ↓
LevelOneSession 交易邊界
   ├─ 無機械 effect：直接保存候選狀態
   ├─ effect 成功：保存含 Reaction／active effect 的狀態
   └─ effect 失敗：只保存死亡基線，不消耗 Reaction
           ↓
ProgressStore 保存 v2；場景照常快速重生
```

導演不知道 Phaser、Sprite、Tween 或 DOM；場景不知道死亡門檻與反應排序。

## 保存格式 v2

- 全域：總死亡數、各關卡狀態、已發現彩蛋、全域反應。
- 關卡：死亡數、嘗試編號、目前進度標記／順序、死因統計、阻礙狀態、是否完成。
- 阻礙：累積死亡、當前連續死亡、連敗所屬進度標記、已播放 reaction ID、持續生效 effect ID。
- v1 僅有 `totalDeaths`；遷移時保留該數值，其餘欄位使用安全預設值。
- 無法驗證或無法遷移的內容退回全新 v2，不讓遊戲白畫面。

## 確定性選擇

同一死亡事件完成狀態更新後，候選 reaction 必須：

1. 關卡與 blocker 相符。
2. threshold 小於等於目前連續死亡數。
3. 尚未完整播放。

候選依 `priority` 由高到低、`threshold` 由低到高、`id` 字典序排列，只選第一個。正常流程會依序在 2／3／5／7 次觸發；若舊保存漏過某門檻，也會先補最早尚未播放的反應，不會一口氣堆疊演出。

## 垂直切片內容映射

### blocker：`first-gap`

| 次數 | tier | effect | 世界演出 |
| --- | --- | --- | --- |
| 2 | 1 | 無 | 紅筆吐槽「這個坑今天有點積極。」 |
| 3 | 2 | `move-first-landing` | 落腳平台向玩家滑近，辯稱今天風大 |
| 5 | 3 | `deploy-gap-spring` | 坑邊出現臨時工安彈簧 |
| 7 | 4 | `deploy-gap-bridge` | 紙膠帶橋直接封住缺口並寫「算了」 |

### blocker：`warning-strip`

| 次數 | tier | effect | 世界演出 |
| --- | --- | --- | --- |
| 2 | 1 | 無 | 「完全安全」標示開始心虛 |
| 3 | 2 | `shrink-warning-strip` | 危險帶縮短，假裝是正常耗損 |
| 5 | 3 | `deploy-strip-bypass` | 上方加設臨時繞行平台 |
| 7 | 4 | `retire-warning-strip` | 危險帶打卡下班，碰撞失效 |

所有機械 effect 都加入 active effect 清單；重新整理、重開本關與 checkpoint 重生後仍生效。

## 進度標記

| marker | order | 意義 |
| --- | --- | --- |
| `start` | 0 | 起點與第一跳躍坑之前 |
| `after-first-gap` | 1 | 已跨過第一坑，建立 checkpoint |
| `after-warning-strip` | 2 | 已跨過危險帶，建立 checkpoint |
| `goal` | 3 | 已到終點 |

只有進入更高 order 才算新進度。前進後所有 blocker 的局部連敗歸零，但累積死亡、已播放反應與 active effect 保留。

## 場景安全

- 死亡鎖在建立 `DeathEvent` 前取得，避免同一生命多次計數。
- effect 套用失敗只記錄錯誤；不保存該 reaction 或 active effect，仍執行 900 ms 重生。
- effect 回傳失敗或意外擲出例外都由工作階段交易邊界收斂；死亡本身照常保存，後續生命可重試同一 reaction。
- 場景建立時先從保存狀態還原 active effect，再允許玩家操作。
- tier 4 必須提供不需原精準技巧的連續通路。
- 手機主要平台維持在底部觸控安全帶以上。

## 驗證

- 純資料測試：門檻、排序、去重、進度重設、未知 blocker、v1 遷移。
- 交易測試：效果成功才保存 active effect；失敗回傳及例外都只保存死亡基線，且下一次死亡可重試。
- 場景瀏覽器測試：連死 2／3／5／7 次時只出現一個對應演出，重新整理後 effect 仍在。
- 完成路徑：無援助可由熟練操作通過；tier 4 不需精準跳躍即可通過。

## 第一階段結果（2026-07-16）

- 完成純資料 `SympathyDirector`、事件去重、固定排序與 2／3／5／7 門檻。
- 保存格式升級為 v2，支援 v1 死亡總數遷移、損毀資料回復與儲存失敗降級。
- `first-gap` 與 `warning-strip` 各有四階反應，其中三階會改寫世界並在重新整理後還原。
- 捲動場景已包含兩個 checkpoint 與終點；新進度會清除局部連敗但保留累積紀錄與援助。
- 原地等待彩蛋會保存為一次性發現，不使用背景分頁時間，也不提高援助門檻。
- 純資料驗證共 18 項測試通過；桌面、手機橫向與手機直向瀏覽器視覺檢查通過。
- 完整可玩流程仍需補標題、暫停／重新開始、結算與正式試玩校正，故 SPEC-0001 尚未宣告完成。
