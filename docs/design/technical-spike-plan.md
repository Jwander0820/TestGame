# 技術尖峰計畫：瀏覽器平台遊戲骨架

- 狀態：已核准執行
- 日期：2026-07-15
- 關聯：ADR-0001、SPEC-0001、SPEC-0002

## 目的

用可拋棄但具正式品質門檻的最小骨架，驗證 Phaser 能支援靜態部署、平台碰撞、桌面／手機共同輸入、橫向縮放與本機死亡計數。尖峰不核准 SPEC-0002 尚待討論的 2／3／5／7 援助門檻。

## 技術範圍

- Vite + TypeScript + Phaser。
- 單一遊戲場景及 DOM 外殼。
- 固定邏輯解析度的橫向 Canvas，自適應可用視窗。
- Phaser Arcade Physics 的移動、跳躍、平台與致命區。
- 鍵盤與三個觸控控制共用一份動作狀態。
- 一次死亡只計數一次、短延遲後安全重生。
- 使用 `localStorage` 保存具版本的最小死亡狀態。
- 角色在有效遊玩狀態原地站立約 8 秒時，觸發一次等待彩蛋；背景時間不計入。
- 正式建置輸出可由純靜態伺服器載入。

## 模組邊界

| 模組 | 責任 | 不負責 |
| --- | --- | --- |
| `game/config` | Phaser 邏輯解析度、縮放、物理與場景註冊 | 關卡內容 |
| `game/input` | 鍵盤／觸控轉成左、右、跳動作 | 角色速度與物理 |
| `game/scenes` | 尖峰場景生命週期與物件組裝 | 長期內容資料格式 |
| `game/player` | 移動、跳躍、死亡鎖與重生 | 選擇援助事件 |
| `game/state` | 保存版本、驗證、載入與重設 | 雲端同步 |
| DOM 外殼 | 標題、狀態、觸控按鈕、旋轉提示與可存取性 | 遊戲世界碰撞 |

## 風險控制

- 不把觸控按鈕寫進遊戲世界座標，避免縮放後命中區失真。
- 不以渲染幀數計算物理門檻。
- 死亡狀態使用鎖避免多個致命碰撞重複計數。
- 保存資料必須先驗證版本及欄位，再交給遊戲使用。
- Canvas 外層保留鍵盤焦點與 DOM 控制，確保可見 focus 狀態。
- 遵守安全區、44×44 px 以上觸控目標、至少 8 px 間距及 reduced-motion。

## 成功門檻

1. 型別檢查、單元測試與正式建置通過。
2. 鍵盤與觸控抽象能驅動同一角色。
3. 同一次死亡不會重複計數；重新整理後計數仍存在。
4. 直向手機顯示旋轉提示；橫向畫面無必要資訊裁切。
5. `dist/` 由靜態伺服器提供時可完成移動、跳躍、死亡與重生。
6. 原地等待彩蛋只使用有效遊玩時間，切換分頁不會誤觸發。
7. 尖峰結果與限制回寫 `docs/logs/`，再決定哪些骨架可升級為正式實作。
