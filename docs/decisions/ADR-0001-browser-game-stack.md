# ADR-0001：瀏覽器遊戲技術方案

- 狀態：提案
- 日期：2026-07-15
- 決策者：待使用者確認

## 背景

產品是支援桌面與手機瀏覽器的 2D 橫向平台遊戲，需處理物理碰撞、動畫、鏡頭、鍵盤／觸控、音訊、場景與存檔，同時維持純靜態網站部署能力。

## 候選方案

### A. Vite + TypeScript + Phaser（建議）

Phaser 專為瀏覽器 2D 遊戲設計，支援 WebGL／Canvas、場景、輸入、音效、動畫與物理；官方提供 Vite + TypeScript 範本。Vite 正式建置產生的 `dist/` 可部署到靜態網站服務。

優點：

- 與目標平台直接一致，不需要後端或玩家安裝引擎。
- 省去自行建造遊戲迴圈、碰撞、輸入與資產載入基礎設施。
- TypeScript 有利於維持陷阱、援助規則與關卡資料的契約。
- 內容仍可使用一般網頁的 HTML／CSS 包裝設定與輔助介面。

代價：

- 專案需管理 JavaScript 套件與建置流程。
- 團隊需熟悉 Phaser 的 Scene、Arcade Physics、Input 與 Scale API。
- 仍需自行設計遊戲架構；框架不會代替關卡與演出設計。

### B. 原生 Canvas + TypeScript

優點是依賴較少、完全掌控底層；缺點是需自行處理物理、鏡頭、輸入、音效、場景與資產生命週期，會把大量時間用在非差異化基礎設施。

### C. 桌面遊戲引擎後輸出 Web

可獲得視覺化編輯器與成熟工作流，但本產品以 Web 為第一平台；在需求尚小時，額外的引擎輸出層與工具鏈不一定帶來相稱收益。若未來轉向大型關卡、美術團隊協作或原生商店版本，再重新評估。

## 建議決策

採用 A：Vite + TypeScript + Phaser，先以 Phaser 的輕量 2D 物理能力完成垂直切片。介面不先引入 React／Vue，除非後續規格顯示有大量 Canvas 外的應用介面需求。

## 靜態部署說明

「使用 Phaser」與「部署成靜態網頁」不衝突。開發時由 Vite 提供本機伺服器；正式建置後輸出 HTML、JavaScript、CSS 與遊戲資產到 `dist/`，部署端只需提供靜態檔案。

## 驗證方式

技術尖峰需證明：

1. `npm run build` 可成功產生靜態 `dist/`。
2. 以本機靜態伺服器開啟 `dist/` 後可完成一段平台移動與重生流程。
3. 鍵盤與觸控輸入能驅動相同的抽象動作。
4. 桌面與常見手機橫向尺寸不裁切必要遊戲資訊。
5. 瀏覽器重新整理後可讀取本機死亡計數。
