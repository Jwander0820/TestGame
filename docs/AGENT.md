## 工作入口

開始先讀本文件與 STATUS.md，查看 Git 工作樹，再按任務讀相關規格與模組。不要預設掃讀全部歷史日誌或載入無關技能。所有文件、使用者文案、提交說明使用繁體中文。

## 授權與 SDD

先有可驗收規格再改產品程式。使用 [規格範本](templates/feature-spec-template.md) 記錄目標、非目標、正常／邊界行為、桌面／觸控、驗收條件及驗證方法。

使用者明確要求的工作可作為對應範圍的核准依據，需在規格記錄日期與來源；完成規格後持續實作、驗證、紀錄，不為一般可逆細節重複詢問。超出範圍或會改變產品方向的提案保持「草案」，不能自行視為核准。使用者要求暫停時立即停下並交接；後續明確恢復指示只恢復其授權範圍。

保護工作樹與既有內容；大幅改寫文件先保留來源。破壞性清理、對外發布與提交依下方 Git 邊界處理。

## 不可破壞的產品約定

- 核心是「遊戲因玩家死亡而逐漸同情玩家，以世界內荒謬事件作弊幫忙」。不能退化成難度選單或只降數值。
- 死亡要推進內容；援助可測試、可重現，不讓隨機性阻止通關。
- 桌面鍵盤與手機觸控同等重要；維持靜態網站能力。
- 不複製參考作品的關卡、角色、素材、音效或文案。

## 程式與美術

- TypeScript 嚴格型別，不用 any 逃避設計。
- 關卡資料、援助規則、狀態交易、世界效果與呈現分離；沿用根 README 的模組邊界。
- 改物理、輸入、保存格式或陷阱／援助規則前，先確認相應規格及回歸案例。
- 美術依 SPEC-0005、當前增補規格與 MASTER。統一像素密度、色盤與輪廓；實際截圖是驗收證據，程式測試不能判定美感。
- 資產記錄來源、用途及核准狀態；試作／退件不得冒充正式核准資產。不納入來源不明素材。
- 不提交密鑰、個資、建置輸出、套件快取或臨時驗證檔。

## 按風險驗證

| 變更 | 必要驗證 |
| --- | --- |
| 純文件 | 連結、內容一致性、git diff --check |
| 程式 | typecheck、受影響測試；影響產物時 build |
| 保存／輸入／物理／陷阱／援助 | 加相關整合或幾何檢查；重生、連續死亡、援助不卡死 |
| 美術／版面／里程碑 | 加實際桌面與手機尺寸截圖、遮擋、焦點、觸控可達；必要整關路線 |

Windows 使用 npm.cmd。完整命令在根 README；測試頁在 tests/browser，操作說明在 docs/testing。檢查通過後不要無理由擴大或重複；新增失敗或修改才重跑相關部分。真人手感與真實觸控尚未驗證時如實記錄，不用桌面模擬冒充。

## Git 與紀錄

- 只使用本機 Git。使用者明確說 commit 才 stage／commit；不推定 push、遠端、PR、部署或發布授權。
- 提交前檢查差異，不混入無關修改；使用 `feat|fix|docs|refactor|test|chore: 繁體中文摘要`。階段可獨立回滾，不使用破壞性重置覆蓋內容。
- 規格記需求與核准來源，ADR 記重大決策，logs 記事實與驗證，STATUS 只摘要當前狀態並連到來源。
- 文件標示狀態與日期；歷史證據不能宣稱為本次測試。已完成、已驗證、待使用者驗收三者分開記錄。
